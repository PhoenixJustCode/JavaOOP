=====================================
Когда использовать Interface, а когда Abstract Class?
=====================================

--- Абстрактный класс (Abstract Class) ---

Используем когда:
1) Классы имеют общего "родителя" и разделяют общий код (поля, методы)
2) Нужно хранить состояние (переменные экземпляра)
3) Между классами есть отношение "IS-A" (является)

Пример: Shape - это общий родитель для Triangle, Cube, Cylinder.
У всех фигур есть площадь (getArea()), но вычисляется по-разному.
Shape хранит общую логику, а каждый подкласс реализует свою формулу.

    abstract class Shape {
        abstract double getArea();  // каждая фигура считает по-своему
    }

    class Triangle extends Shape {
        double a, b, c, height;
        double getArea() { return 0.5 * b * height; }
    }

    class Cube extends Shape {
        int a;
        double getArea() { return 6 * a * a; }
    }


--- Интерфейс (Interface) ---

Используем когда:
1) Нужно описать СПОСОБНОСТЬ / ПОВЕДЕНИЕ, а не тип объекта
2) Класс может реализовать несколько интерфейсов (множественное наследование поведения)
3) Между классами нет общего предка, но у них есть одинаковое поведение

Пример: Perimeter, Volume, LateralSurfaceArea - это способности.
Куб имеет и периметр, и объем, и боковую площадь.
Треугольник имеет только периметр.
Цилиндр имеет объем и боковую площадь, но не периметр.

    interface Perimeter {
        double getPerimeter();
    }

    interface Volume {
        double getVolume();
    }

    // Cube реализует ВСЕ интерфейсы - множественное "наследование"
    class Cube extends Shape implements Volume, LateralSurfaceArea, Perimeter { ... }

    // Triangle реализует только Perimeter
    class Triangle extends Shape implements Perimeter { ... }


--- Ключевые различия ---

| Критерий              | Abstract Class         | Interface              |
|-----------------------|------------------------|------------------------|
| Множественное наслед. | Нет (только 1 класс)   | Да (сколько угодно)    |
| Поля (состояние)      | Да                     | Только static final    |
| Конструктор           | Да                     | Нет                    |
| Модификаторы доступа  | Любые                  | public (по умолчанию)  |
| Когда использовать    | Общий предок с кодом   | Общее поведение        |
| Отношение             | "IS-A" (является)      | "CAN-DO" (умеет)       |

Вывод: Используйте abstract class когда классы - это разновидности одного типа.
       Используйте interface когда классам нужна общая способность.
